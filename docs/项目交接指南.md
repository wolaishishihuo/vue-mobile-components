# 📦 Vue Mobile Components 项目交接指南

> **3 步完成交接和发布**：运行脚本 → 登录 npm → 发布

---

## 🚀 快速开始（5 分钟）

### 步骤 1：运行自动化配置脚本

```bash
cd vue-mobile-components

# 运行配置脚本
./scripts/update-npm-config.sh

# 按提示输入 3 个信息：
# 1. npm scope (例如: my-company 或 my-username)
# 2. 作者名称 (例如: Zhang San)
# 3. Git 仓库地址 (例如: https://github.com/username/repo.git)
```

**脚本会自动完成**：
- ✅ 更新所有 package.json 中的包名和作者
- ✅ 将内部依赖改为 `workspace:*`（关键！避免安装失败）
- ✅ 更新 .npmrc、tsconfig.json、vite.config.ts
- ✅ 更新所有文档和代码中的包名引用
- ✅ 更新 GitHub Actions 工作流
- ✅ 重新安装依赖
- ✅ 自动备份原配置

### 步骤 2：登录 npm

```bash
# 登录 npm 账号
npm login
# 输入用户名、密码、邮箱

# 验证登录
npm whoami
```

**如果使用组织 scope**（如 `@company-name/xxx`）：
1. 访问：https://www.npmjs.com/org/create
2. 创建组织（名称与 scope 一致）
3. 选择免费计划（只能发布公开包）

**如果使用个人 scope**（如 `@username/xxx`）：
- 无需创建组织，直接使用你的用户名

### 步骤 3：构建并发布

```bash
# 0. 确保代码已提交（重要！pnpm 会检查 Git 状态）
git status
git add .
git commit -m "chore: ready for first publish"

# 1. 构建所有包（生成 dist 目录，必须先执行！）
pnpm build

# 2. 发布到 npm（会按依赖顺序自动发布 core → components → business）
# macOS/Linux:
pnpm -r --filter='!playground' publish --access public

# Windows (使用双引号):
pnpm -r --filter="!playground" publish --access public

# 3. 验证发布成功
npm view @your-scope/core
npm view @your-scope/components
npm view @your-scope/business
```

> ⚠️ **重要提醒**：
> 1. **Windows 用户**：必须使用双引号 `"!playground"`
> 2. **必须先 build 再 publish**：publish 上传的是 `dist/` 目录，不 build 会发布空包或旧代码
> 3. **Git 检查**：发布前必须提交代码，否则会报错 "Unclean working tree"

**完成！** 🎉

## 📋 详细说明

### npm scope 类型

**个人 scope** (`@your-username/xxx`)：
- ✅ 无需创建组织
- ✅ 直接使用 npm 用户名
- ✅ 适合个人项目

**组织 scope** (`@company-name/xxx`)：
- 需要在 npm 创建组织
- 适合团队项目
- 免费计划只能发布公开包

### 为什么要用 workspace:* 协议？

**问题**：如果内部依赖使用具体版本号（如 `"@new-scope/core": "^1.0.0"`）
- 运行 `pnpm install` 会从 npm 下载
- 但新包名还没发布，导致安装失败 ❌

**解决**：使用 `workspace:*` 协议
- 从本地工作区加载包
- 不从 npm 下载 ✅
- 发布时 pnpm 自动转换为实际版本号

**脚本已自动处理这个问题！**

### 发布顺序

pnpm 会按依赖关系自动排序：
1. `@your-scope/core` - 无依赖，最先发布
2. `@your-scope/themes` - 无依赖
3. `@your-scope/components` - 依赖 core
4. `@your-scope/business` - 依赖 core 和 components

## 🔧 后续开发

### 版本发布流程（使用 Changesets）

```bash
# 1. 开发完成后，创建变更记录
pnpm changeset
# 选择要发布的包、版本类型（patch/minor/major）、输入变更说明

# 2. 更新版本号
pnpm changeset version

# 3. 提交版本变更
git add . && git commit -m "chore: version packages"

# 4. 构建并发布
pnpm build && pnpm changeset publish

# 5. 推送代码和标签
git push && git push --tags
```

### 包结构

```
packages/
├── core/         @your-scope/core - 工具函数、hooks、类型定义
├── components/   @your-scope/components - 基础 UI 组件
├── business/     @your-scope/business - 业务组件
├── themes/       @your-scope/themes - 主题系统
└── playground/   不发布 - 开发调试环境
```

## ❌ 常见问题

### Q1: 提示 "Unclean working tree. Commit or stash changes first"？

**原因**：Git 工作区有未提交的更改，pnpm 会检查以确保不发布未提交的代码

**解决**：
```bash
# 方案一：提交更改（推荐）
git add .
git commit -m "chore: prepare for publish"
pnpm -r --filter="!playground" publish --access public

# 方案二：跳过 Git 检查（仅用于测试）
pnpm -r --filter="!playground" publish --access public --no-git-checks
```

### Q2: 为什么必须先 `pnpm build` 再 `pnpm publish`？

**原因**：publish 上传的是 `dist/` 目录的编译产物，不是源代码

**说明**：
- `pnpm build` - 编译 TS → JS，生成 `dist/` 目录
- `pnpm publish` - 上传 `dist/` 到 npm

**如果不先 build**：
- ❌ `dist/` 不存在 → 发布失败或空包
- ❌ `dist/` 是旧的 → 发布过时代码

**正确流程**：
```bash
pnpm build                    # 1. 生成最新 dist/
pnpm -r --filter="!playground" publish  # 2. 上传到 npm
```

### Q3: Windows 上提示 "No projects matched the filters"？

**原因**：Windows 命令行不支持单引号

**解决**：使用双引号
```bash
# ❌ 错误 (Windows)
pnpm -r --filter='!playground' publish --access public

# ✅ 正确 (Windows)
pnpm -r --filter="!playground" publish --access public

# ✅ 或者省略引号
pnpm -r --filter=!playground publish --access public
```

### Q4: 执行脚本后 pnpm install 失败？

**检查**：确认脚本已将内部依赖改为 `workspace:*`

```bash
# 查看 packages/components/package.json
cat packages/components/package.json | grep workspace

# 应该看到：
# "@your-scope/core": "workspace:*"
```

如果不是，手动修改后重新安装：
```bash
pnpm install
```

### Q5: 发布时提示 403 Forbidden？

**原因**：没有权限

**解决**：
```bash
# 1. 确认已登录
npm whoami

# 2. 如果使用组织，确保已创建组织且是成员
npm org ls @your-scope

# 3. 确保设置为公开包（package.json 中已配置）
# "publishConfig": { "access": "public" }
```

### Q6: 发布时提示 402 Payment Required？

**原因**：尝试发布私有包但使用免费账号

**解决**：
```bash
# 必须使用 --access public
pnpm -r --filter='!playground' publish --access public
```

### Q7: 发布时提示包名已存在？

**原因**：npm 上已有同名包

**解决**：
```bash
# 在 npm 搜索
npm search @your-scope/core

# 如果已存在，重新运行脚本选择不同的 scope
./scripts/update-npm-config.sh
```

### Q8: TypeScript 类型找不到？

**检查**：
```bash
# 1. 确认 dist 目录有类型文件
ls packages/core/dist/index.d.ts

# 2. 如果没有，重新构建
pnpm --filter @your-scope/core build

# 3. 确认 package.json 中的 types 字段
# "types": "./dist/index.d.ts"
```

### Q9: GitHub Actions 构建失败？

**原因**：Actions 中可能还有旧的包名

**解决**：脚本已自动更新 GitHub Actions 工作流文件

如果还有问题，检查 `.github/workflows/` 下的文件

## 🔒 安全建议
