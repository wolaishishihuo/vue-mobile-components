# 📦 发布指南

> **首次交接项目？** 请先查看 [项目交接指南.md](./项目交接指南.md)

## 🚀 日常版本发布（4步）

### 1️⃣ 创建变更记录
```bash
pnpm changeset
# 选择要发布的包
# 选择版本类型（patch/minor/major）
# 输入变更说明
```

### 2️⃣ 更新版本号
```bash
pnpm changeset version
# 自动更新 package.json 和 CHANGELOG.md
```

### 3️⃣ 构建并发布
```bash
pnpm build && pnpm changeset publish

# 或手动发布:
# macOS/Linux:
pnpm -r --filter='!playground' publish --access public
# Windows:
pnpm -r --filter="!playground" publish --access public
```

### 4️⃣ 提交并推送
```bash
git add . && git commit -m "chore: version packages"
git push && git push --tags
```

## 📦 包结构

```
packages/
├── core/         # @jname/core - 工具包
├── components/   # @jname/components - 基础组件
├── business/     # @jname/business - 业务组件
├── themes/       # @jname/themes - 主题包
└── playground/   # 开发环境（不发布）
```

## 🏷️ 版本类型

- **patch** (1.0.0 → 1.0.1): 修复bug
- **minor** (1.0.0 → 1.1.0): 新增功能
- **major** (1.0.0 → 2.0.0): 破坏性更改

## 💡 常用命令

```bash
# 开发调试
pnpm dev                    # 启动playground

# 代码检查
pnpm lint                   # 代码格式检查
pnpm typecheck             # 类型检查

# 构建相关
pnpm build                  # 构建所有包
pnpm clean                  # 清理构建产物

# 发布相关
pnpm changeset             # 交互式创建changeset
pnpm changeset version     # 更新版本号
pnpm changeset publish     # 发布到npm
```

## ⚡ 一键发布脚本

想要更简单？在项目根目录运行：

```bash
# 创建一个快速发布脚本
cat > quick-publish.sh << 'EOF'
#!/bin/bash
echo "🚀 开始发布流程..."

# 1. 检查是否有未提交的修改
if [[ -n $(git status -s) ]]; then
  echo "📝 提交当前修改..."
  git add .
  read -p "请输入提交信息: " commit_msg
  git commit -m "$commit_msg"
fi

# 2. 更新版本号
echo "📊 更新版本号..."
pnpm changeset version

# 3. 构建和发布
echo "🔨 构建所有包..."
pnpm build

echo "📦 发布到npm..."
pnpm changeset publish

# 4. 提交版本变更
echo "💾 提交版本变更..."
git add .
git commit -m "chore: version packages"

echo "✅ 发布完成！"
EOF

chmod +x quick-publish.sh
```

使用：`./quick-publish.sh`

## 🔍 发布验证

发布后验证：

```bash
# 查看包信息
npm view @jname/business

# 查看所有版本
npm view @jname/business versions --json

# 本地测试安装
npm install @jname/business@latest
```

## ⚠️ 注意事项

1. **changeset文件格式**：严格按照yaml格式编写
2. **包名准确**：确保包名正确（@jname/core, @jname/components, @jname/business）
3. **网络权限**：发布需要npm登录和网络访问权限
4. **构建检查**：发布前确保构建成功
5. **依赖关系**：系统会自动处理包间依赖发布顺序
