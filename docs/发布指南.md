# 📦 Vue Mobile Components 发布指南

本文档详细说明了如何发布和管理Vue Mobile Components组件库的版本。

## 🚀 发布前准备

### 1. 环境要求

- Node.js >= 18
- pnpm >= 8
- npm账号并已登录
- GitHub仓库访问权限

### 2. 检查清单

在发布之前，请确保：

- [ ] 所有代码已提交到Git
- [ ] 代码通过所有测试和检查
- [ ] 文档已更新
- [ ] CHANGELOG.md已更新
- [ ] 版本号符合语义化版本规范

## 📋 版本管理

项目采用[语义化版本](https://semver.org/)规范：

- **MAJOR (主版本号)**: 不兼容的API更改
- **MINOR (次版本号)**: 向后兼容的功能性新增
- **PATCH (修订号)**: 向后兼容的问题修正

## 🔧 本地发布流程

### 1. 手动发布

```bash
# 1. 确保代码最新
git pull origin main

# 2. 安装依赖
pnpm install

# 3. 运行检查
pnpm lint
pnpm typecheck

# 4. 构建
pnpm build

# 5. 登录npm（如果未登录）
npm login

# 6. 发布
npm publish
```

### 2. 使用脚本发布

```bash
# 补丁版本发布 (1.0.0 -> 1.0.1)
pnpm release:patch

# 次要版本发布 (1.0.0 -> 1.1.0)
pnpm release:minor

# 主要版本发布 (1.0.0 -> 2.0.0)
pnpm release:major
```

这些脚本会自动：

- 更新版本号
- 创建git tag
- 构建项目
- 发布到npm

## 🤖 自动化发布流程

### 1. GitHub Actions配置

项目已配置自动化发布流程，当推送tag时自动触发：

```bash
# 创建并推送tag触发自动发布
git tag v1.0.1
git push origin v1.0.1
```

### 2. 配置GitHub Secrets

在GitHub仓库设置中添加以下secrets：

1. **NPM_TOKEN**:
   - 登录 [npmjs.com](https://www.npmjs.com)
   - 进入 Access Tokens 页面
   - 创建 Automation token
   - 将token添加到GitHub Secrets

2. **GITHUB_TOKEN**:
   - GitHub自动提供，无需手动配置

### 3. 自动发布流程

自动发布会执行以下步骤：

1. ✅ 检查代码
2. ✅ 安装依赖
3. ✅ 运行lint检查
4. ✅ 运行类型检查
5. ✅ 构建组件库
6. ✅ 发布到npm
7. ✅ 创建GitHub Release

## 📖 发布流程详解

### 1. 准备发布

```bash
# 1. 切换到主分支
git checkout main
git pull origin main

# 2. 确保工作目录干净
git status

# 3. 更新依赖
pnpm install

# 4. 运行所有检查
pnpm lint
pnpm typecheck
pnpm build
```

### 2. 更新版本信息

```bash
# 手动更新版本
npm version patch  # 或 minor/major

# 或使用项目脚本
pnpm version:patch
```

### 3. 更新CHANGELOG

在 `CHANGELOG.md` 中添加新版本的更新内容：

```markdown
## [1.0.1] - 2024-01-20

### 新增

- 新增XXX功能

### 修复

- 修复XXX问题

### 变更

- 优化XXX逻辑
```

### 4. 提交并发布

```bash
# 提交更改
git add .
git commit -m "chore: release v1.0.1"

# 推送到远程
git push origin main

# 创建并推送tag（触发自动发布）
git tag v1.0.1
git push origin v1.0.1
```

## 🚨 常见问题

### 1. 发布失败

**问题**: npm publish失败

```bash
npm ERR! You need to auth this request
```

**解决**: 重新登录npm

```bash
npm logout
npm login
```

### 2. 版本冲突

**问题**: 版本号已存在

```bash
npm ERR! You cannot publish over the previously published versions
```

**解决**: 更新版本号

```bash
npm version patch
```

### 3. GitHub Actions失败

**问题**: 自动发布失败

**检查**:

- NPM_TOKEN是否正确配置
- 代码是否通过所有检查
- 版本号是否重复

## 📚 最佳实践

### 1. 发布频率

- **补丁版本**: 修复bug时及时发布
- **次要版本**: 新功能稳定后发布
- **主要版本**: 重大更改时谨慎发布

### 2. 版本规划

- 保持向后兼容性
- 详细记录破坏性更改
- 提供迁移指南

### 3. 质量保证

- 发布前充分测试
- 使用CI/CD确保代码质量
- 定期更新依赖
