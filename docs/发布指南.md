# 📦 Vue Mobile Components 发布指南

本文档说明了 Monorepo 架构下的组件库发布流程。

## 🏗️ Monorepo 架构

项目采用 pnpm workspaces + Changesets 管理多包发布：

```
packages/
├── core/         # @jname/core
├── components/   # @jname/components
├── business/     # @jname/business
├── themes/       # @jname/themes
└── playground/   # 开发环境（不发布）
```

## 🚀 发布流程

### 1. 开发完成检查

```bash
# 代码质量检查
pnpm lint
pnpm typecheck

# 构建所有包
pnpm build

# 确保所有包正常构建
```

### 2. 创建变更集

```bash
# 交互式创建变更记录
pnpm changeset

# 选择要发布的包和版本类型
# 添加变更描述
```

### 3. 更新版本号

```bash
# 根据变更集更新版本号
pnpm version-packages

# 这会更新 package.json 和生成 CHANGELOG
```

### 4. 发布到 npm

```bash
# 发布所有有变更的包
pnpm publish-packages

# 或单独发布某个包
pnpm --filter @jname/core release
pnpm --filter @jname/components release
pnpm --filter @jname/business release
```

## 🔧 快捷命令

### 完整发布流程

```bash
# 一键构建并发布所有包
pnpm release

# 单独发布核心包
pnpm release:core

# 单独发布组件包
pnpm release:components

# 单独发布业务包
pnpm release:business
```

### 开发调试

```bash
# 启动 playground 开发环境
pnpm dev

# 监听构建（开发时）
pnpm build:watch
```

## 📝 Changesets 工作流

### 1. 变更类型

- **patch**: 修复 bug，不影响 API
- **minor**: 新增功能，向后兼容
- **major**: 破坏性更改，不向后兼容

### 2. 包依赖发布

当发布有依赖关系的包时，Changesets 会自动：

- 按依赖顺序发布包
- 更新依赖包的版本号
- 确保依赖关系正确

### 3. 发布策略

```bash
# 发布所有包（推荐）
pnpm changeset
pnpm version-packages
pnpm publish-packages

# 发布特定包
pnpm changeset --filter @jname/components
```

## 🛡️ 发布验证

### 1. 本地验证

```bash
# 检查包内容
npm pack --dry-run

# 在测试项目中验证
cd test-project
npm install @jname/components@latest
```

### 2. 线上验证

```bash
# 查看包信息
npm view @jname/components

# 查看所有版本
npm view @jname/components versions --json
```

## 🚨 应急处理

### 撤回错误发布

```bash
# 撤回24小时内的包（谨慎使用）
npm unpublish @jname/components@1.0.0

# 废弃某个版本
npm deprecate @jname/components@1.0.0 "This version has critical bugs"
```
