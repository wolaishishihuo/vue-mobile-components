# 📋 Vue Mobile Components 项目交接配置指南

## 🎯 概述

本指南帮助新维护者将项目发布到自己的 npm 账号/组织下。

---

## ⚙️ 配置修改步骤

### 1️⃣ 修改 npm scope（包名前缀）

当前包名使用 `@jname` 作为 scope，需要改为新的 scope，例如 `@your-org` 或 `@your-username`。

#### 需要修改的文件：

**根目录 package.json** (`/package.json`)
```json
{
  "name": "@your-org/vue-mobile-components-monorepo",  // 修改这里
  "author": "Your Name",  // 修改作者
  "repository": {
    "type": "git",
    "url": "https://github.com/your-username/vue-mobile-components.git"  // 修改仓库地址
  }
}
```

**packages/core/package.json**
```json
{
  "name": "@your-org/core",  // 修改这里
  "author": "Your Name"      // 修改作者
}
```

**packages/components/package.json**
```json
{
  "name": "@your-org/components",  // 修改这里
  "author": "Your Name",           // 修改作者
  "dependencies": {
    "@your-org/core": "^1.0.1"     // 修改依赖
  }
}
```

**packages/business/package.json**
```json
{
  "name": "@your-org/business",    // 修改这里
  "author": "Your Name",           // 修改作者
  "dependencies": {
    "@your-org/components": "^1.0.2",  // 修改依赖
    "@your-org/core": "^1.0.1"         // 修改依赖
  }
}
```

**packages/themes/package.json**
```json
{
  "name": "@your-org/themes",  // 修改这里
  "author": "Your Name"        // 修改作者
}
```

**packages/playground/package.json** (如果有)
```json
{
  "dependencies": {
    "@your-org/business": "workspace:*",
    "@your-org/components": "workspace:*",
    "@your-org/core": "workspace:*"
  }
}
```

### 2️⃣ 修改 Changeset 配置

**`.changeset/config.json`**
```json
{
  "$schema": "https://unpkg.com/@changesets/config@3.0.0/schema.json",
  "changelog": "@changesets/cli/changelog",
  "commit": false,
  "fixed": [],
  "linked": [],
  "access": "public",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": ["@your-org/playground"]  // 修改这里
}
```

---

### 3️⃣ 修改文档中的示例

需要更新所有文档中的包名引用：

**CLAUDE.md** 和 **README.md** 中的示例：
```typescript
// 旧的引用
import { useRefreshList } from '@jname/core'
import { JTabs, JContentCard } from '@jname/components'
import { JOrganization } from '@jname/business'

// 改为
import { useRefreshList } from '@your-org/core'
import { JTabs, JContentCard } from '@your-org/components'
import { JOrganization } from '@your-org/business'
```

**安装命令更新：**
```bash
# 旧命令
npm install @jname/core @jname/components @jname/business

# 改为
npm install @your-org/core @your-org/components @your-org/business
```

---

### 4️⃣ 一键批量替换脚本

为了简化修改过程，可以使用以下脚本批量替换：

```bash
#!/bin/bash

# 设置新的 scope 名称
NEW_SCOPE="your-org"  # 修改为你的 scope
OLD_SCOPE="jname"

# 设置新的作者名
NEW_AUTHOR="Your Name"

# 设置新的仓库地址
NEW_REPO="https://github.com/your-username/vue-mobile-components.git"

echo "🔄 开始批量替换配置..."

# 1. 替换所有 package.json 中的包名
find . -name "package.json" -not -path "*/node_modules/*" -exec sed -i '' "s/@${OLD_SCOPE}/@${NEW_SCOPE}/g" {} \;

# 2. 替换作者信息
find . -name "package.json" -not -path "*/node_modules/*" -exec sed -i '' "s/\"author\": \"Jname\"/\"author\": \"${NEW_AUTHOR}\"/g" {} \;

# 3. 替换文档中的包名
find . -name "*.md" -not -path "*/node_modules/*" -exec sed -i '' "s/@${OLD_SCOPE}/@${NEW_SCOPE}/g" {} \;

# 4. 替换 changeset 配置
sed -i '' "s/@${OLD_SCOPE}/@${NEW_SCOPE}/g" .changeset/config.json

echo "✅ 配置替换完成！"
echo ""
echo "⚠️  请手动检查以下内容："
echo "1. 根目录 package.json 中的 repository.url"
echo "2. 各个包的 package.json 中的作者信息"
echo "3. CLAUDE.md 和 README.md 中的示例代码"
```

**使用方法：**
```bash
# 1. 保存脚本为 update-config.sh
# 2. 修改脚本中的 NEW_SCOPE, NEW_AUTHOR, NEW_REPO
# 3. 赋予执行权限
chmod +x update-config.sh

# 4. 执行脚本
./update-config.sh
```

## 🔐 NPM 发布配置

### 1️⃣ 登录 npm

```bash
npm login
# 按提示输入：
# - Username
# - Password
# - Email
# - OTP (如果启用了两步验证)
```

### 2️⃣ 创建组织（可选）

如果使用 `@your-org` 这样的 scope，需要在 npm 上创建组织：

1. 访问：https://www.npmjs.com/org/create
2. 创建组织，名称与 scope 一致
3. 选择组织类型（免费或付费）

**注意**：免费组织只能发布公开包

### 3️⃣ 验证发布权限

```bash
# 检查当前登录用户
npm whoami

# 检查对组织的访问权限
npm org ls @your-org
```

### 4️⃣ 首次发布

```bash
# 1. 清理旧的构建产物
pnpm clean

# 2. 安装依赖
pnpm install

# 3. 构建所有包
pnpm build

# 4. 发布（首次发布）
pnpm -r --filter='!playground' publish --access public
```

## 🚀 后续发布流程

修改配置后，使用标准的 Changeset 工作流：

```bash
# 1. 开发完成后，创建 changeset
pnpm changeset

# 2. 更新版本号
pnpm changeset version

# 3. 构建和发布
pnpm build && pnpm changeset publish

# 4. 提交版本变更
git add . && git commit -m "chore: version packages"
git push
```

## ✅ 配置检查清单

发布前请确认：

- [ ] 所有 `package.json` 中的 `@jname` 已改为新 scope
- [ ] 所有包的 `author` 字段已更新
- [ ] 根目录 `package.json` 的 `repository.url` 已更新
- [ ] `.changeset/config.json` 中的 `ignore` 已更新
- [ ] 文档（CLAUDE.md, README.md）中的示例已更新
- [ ] 已登录正确的 npm 账号
- [ ] 如使用组织，已在 npm 上创建对应组织
- [ ] `publishConfig.access` 设置为 `"public"`（所有包都有）
- [ ] 本地构建成功（`pnpm build`）
- [ ] 类型检查通过（`pnpm typecheck`）
- [ ] 代码检查通过（`pnpm lint`）

## 📝 重要提示

### 关于包名选择

1. **使用个人 scope**: `@your-username/package-name`
   - 无需创建组织
   - 直接使用 npm 用户名
   - 适合个人项目

2. **使用组织 scope**: `@your-org/package-name`
   - 需要创建 npm 组织
   - 适合团队项目
   - 更专业的命名方式

### 关于版本号

建议发布前重置版本号：
```json
{
  "version": "1.0.0"  // 从 1.0.0 开始
}
```

### 关于 pnpm-lock.yaml

执行 `pnpm install` 会自动更新 `pnpm-lock.yaml`，确保提交更新后的文件。

## 🔍 常见问题

### Q1: 发布时提示 403 权限错误？
**A**: 检查是否已登录正确的 npm 账号，如果使用组织，确保当前用户是组织成员。

### Q2: 包名已存在？
**A**: 检查 npm 上是否已有同名包，需要选择不同的 scope 或包名。

### Q3: 发布后其他人安装失败？
**A**: 确认 `publishConfig.access` 设置为 `"public"`，默认组织包是私有的。

### Q4: 依赖版本不匹配？
**A**: 修改包名后运行 `pnpm install` 更新依赖关系。
